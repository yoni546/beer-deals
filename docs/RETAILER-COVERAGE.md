## Where a promotion runs (0.9.0) — the rule

Decided in ONE place, `promotion_scope()` (migration 0017), from the chain's latest scan: **known** = every branch its
Stores file lists (banners we do not carry excluded); **checked** = branches whose current promotions file was read
(re-read or unchanged); **matching** = checked branches whose current file lists the promotion — published by us or
held by our own price check (where it is listed is the evidence).

| Scope | When | The app says |
|---|---|---|
| chainwide | the chain declares it (no feed does today), or every known branch was checked AND every one lists it | בכל הרשת |
| participating_branches | some, but not all, of several checked branches list it | בסניפים משתתפים — "12 מתוך 18 סניפים שנבדקו" in the sheet |
| single_branch | every known branch was checked and exactly one lists it | "<branch> בלבד" |
| unknown | one branch checked; or every checked branch lists it but not every branch was checked; or nothing current | "נצפה בכל 59 הסניפים שנבדקו" / "נצפה בסניף X" / "זמינות לפי סניף" |

A branch that failed, whose newest file is older than 36 h, or that has published nothing yet today is *not checked*:
never counted as lacking a promotion. A promotion's identity across branches: identical terms (kind, quantity, price,
audience, written terms, the day it ends) AND a shared item or promotion id, connected across the chain; dates as
days, ids and item codes without leading zeros — see `termsKey` / `canonicalKeys` in lib/plan.mjs.

**The tables above and the staging database carry the identity as it was before its last refinement** (dates and
ids compared as written; 661 canonical promotions). On the same scan the final rule gives **531** canonical
promotions and no pack shown twice at one chain for the same price and end day (111 such pairs before). Staging
takes it on with each branch's next file (a same-file re-import replays), or at once after a reset of the
run rows — which is the owner's call (FINAL-READINESS-REPORT.md).

## 0.8.0 → 0.9.0

proved the pipeline; the statuses above replace it. The 0.8.0 before/after table and its root causes (six-packs
without a container word, per-unit Quantity, Victory's fetcher, Yochananof's single-statement promotions, the missing
beers) are in this file as released in 0.8.0 (`git show fee8081:docs/RETAILER-COVERAGE.md`) and in docs/LESSONS.md.
